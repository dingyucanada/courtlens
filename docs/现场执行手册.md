# 12 小时现场执行手册

本手册以 2026-09-22 官网已公布任务设计，是团队执行建议，不是官方时间表。赛前代码能否复用、可用模型/服务、数据许可、成片规格等须以培训/现场说明为准。若不允许复用，将本仓库作为练习记录，现场从空仓库重建并保留提交时间。

## 两至三人分工

两人时，A 负责工程与数据：正式字典、适配、指标口径、证据逻辑、后端和云分支联调；B 负责界面演示与素材复核：视频对齐、画面标注、字幕、导出检查和路演。双方交叉核对关键解释，不能由作者自己确认全部事实。

三人时，由 C 独立负责篮球分析、叙事和交付核查；B 聚焦界面与视频流程，A 保留工程与数据职责。队员姓名不代填，报名日期和实际队伍资格按赛方最新通知核对。

## 赛前确认本机产品可用

运行 `python3 server.py --port 8765`，打开 [项目工作区](http://127.0.0.1:8765/projects.html)。检查 FFprobe、FFmpeg 与渲染 Python 的 Pillow；需要语音时检查 macOS 本机 `say` 及中文语音。Windows 当前无此配音能力，亦未完成实机验收。启动与依赖详见 [产品使用手册](产品使用手册.md)、[产品架构与运维](产品架构与运维.md)。

持久项目位于默认 `workspace/` 或指定工作区，视频上传到本机服务保存。提前做一次保存、重开、历史恢复及导出；停止服务后备份整个工作区。双窗口保存冲突时先下载草稿再取最新版，不覆盖他人修改。旧数据缺少复核状态时按草稿处理，项目后台必须明确 `reviewed` 才能导出。

## 推荐工作顺序
| 时间 | 必须形成的结果 | 失败后动作 |
|---|---|---|
| 00:00–00:45 | 读完整规则；保存官方数据原件哈希；确认允许工具、时区、视频许可、交付规格 | 记录实质冲突，仅向组织方询问阻塞点 |
| 00:45–02:00 | 字典、单位、时钟与镜头分段适配；一条回合完整解析 | 不反推官方统计公式；保留原始字段 |
| 02:00–04:00 | 一个真实回合在项目中完成保存、复核、证据→叠加→字幕→MP4 | 先保一个正确闭环；要求语音时实际核验配音，不能拿无声成片替代 |
| 04:00–06:30 | 3–5个有不同解释价值的回合；读图、难投、牵制等主题以数据为准 | 数据缺失则停止相应结论 |
| 06:30–08:00 | 核对来源、引用、时间；检查草稿阻断、版本冲突、任务冻结和至少一个反例 | 修复阻断问题，停止添加支线功能 |
| 08:00–09:30 | 剪出符合官方时长的演示；仓库干净复现 | 云失败披露本地模式；若云为硬要求，仍记为未完成阻断项 |
| 09:30–10:30 | 独立机器/新目录启动，完整播放视频；核对提交文件 | 保留可用版本，不临时升级依赖 |
| 10:30–11:15 | 路演排练、关键问题答辩；冻结成品并校验哈希 | 若复查出错则回退到已测版本 |
| 11:15–12:00 | 预留上传、网络、压缩、字段填写与回执验证 | 只按官方渠道提交；本人完成声明/签署 |

## 领取数据后的八项核对
1. 视频是整场还是剪辑；源FPS、分辨率、编码；是否存在回放/切镜/慢动作。
2. 时间戳是比赛钟、源视频PTS、相对片段秒、帧号还是Unix时间；比赛钟暂停不能直接当视频秒。
3. 球员ID与队伍、球员坐标是脚点/中心点，单位是米/英尺/像素/归一化，是否已透视投影。
4. xFG是0–1还是0–100；“难度”数值是否反向；球员身份是否在模型定义中。
5. Gravity使用什么单位和基准；不得当作最近防守距离、也不得将其直接解释为创造了若干分。
6. Leverage是回合结果机会差、单次事件分配还是球员累计分；必须显式匹配语义，不做猜测归一化。
7. 官方值是否带估计区间、版本、置信度；没有就不制造置信区间。
8. 标注所需坐标和回合边界是否提供；若没有，用允许的人工划段、校准或静态圈画并保留人工来源，不宣称全自动检测。

CSV 必须使用已经映射到视频的秒数。报错中的第 N 行指该记录结束的物理行，多行引号字段会改变行号。非空 Leverage 必须显式确认回合胜率机会差口径，未知就留空；来源与正式字段另存映射表。

## 现场验收门槛（团队建议）
- 所有公开显示的数值均可定位到官方字段或透明计算，缺失值不作零。
- 每句定量解说有证据ID，点击能到达同一事件；推断文字不能写成已证实战术意图。
- 回放、拖动、倍速、切回合时无陈旧叠加；未校准时隐藏追踪图层。人工静态图层须另行复核，限定单镜头区间，保留 `origin=manual`、`frame_reviewed=true` 和 `author_note`，不得借此开启原追踪校准。
- 选取不少于20个官方人工核验锚点，报告叠加时间绝对误差中位数/P95；目标≤2帧，测不到则不得声称达到。
- 选取所有演示句子（不是只挑正确句），人工核对证据支持率及数值一致性；报告分母。
- 实际云模型调用至少一次并保存脱敏响应、耗时、模型ID与区域；没有调用就标“云接入待验证”。
- 在已复核项目上创建导出后再编辑，核对旧任务仍对应创建时版本；检查取消及服务重启后中断任务的失败提示，不声称自动续跑。
- 配音需使用实际可用的本机语音环境，核对音轨、全部字幕和证据记录。两种导出都不混入原音；选择配音后若失败，不接受无声中间成片作为成功结果。
- 官方包从新目录运行；成片全程播放；交付文件和最终仓库提交一致。验收数据填写到 [最终验收报告](最终验收报告.md)，不要把团队目标写成已经达到的实测结果。

## 最终十分钟答辩
- 为什么不从零训练检测器？赛方已经给深度数据；本作品把有限时间用在原视频解释的可靠闭环，输入允许时可接感知模型。
- 引力是否能证明某次跑动导致空位？不能单靠一个指标证明因果。我们区分数据观测、解释性推断和未获证实的意图。
- 是否自己复现了 NBA 专有指标？没有，使用赛方提供值及其版本定义，避免把代理指标冒充官方统计。
- 没网能运行吗？依赖已装好时，本地保存、校验、筛选、解读、标注和导出可用；macOS 本地配音也不调用云服务。独立云规划失败会明确报错，不伪装成云成功。
- 当前最大的弱点？真实 NBA 输入未取得，云模型未实调，Windows 未实机验收；本机产品流程与合成演练不能代替这些验证。
