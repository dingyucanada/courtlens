# CourtLens 观赛透镜：参赛策略与产品方案

版本：v2 本机产品与赛前方案，2026 年 9 月 22 日。当前已形成可持久保存项目、编辑回合、人工标注和后台导出的单用户工作台。正式视频、数据字典与完整评审细则尚未领取；合成演练不等于真实比赛验收，也不承诺获奖。Bedrock 工具规划器仅完成模拟协议测试，尚未用云凭据实调；Windows 服务锁仅做模拟测试，未实机验证。最终实测结果统一见 [最终验收报告](最终验收报告.md)。

## 1. 独特切口：把“为什么”解释回画面

普通观众看到了进球，却未必看到机会如何形成；懂球观众也需要区分可见事实、官方统计和解说推断。CourtLens 的核心不是再报一遍比分，而是把一段值得回看的动作变成“看得见证据的解释”。

一次完整体验只回答三个问题：**为什么选这一回合？画面哪里支持解释？哪些话目前不能说？** 系统选择回合，给出证据，在恰当时刻显示箭头、区域和球员标注，生成同步解说；用户能够回到对应时刻核对，也能让系统改用通俗或分析口径。

参赛主张是“可核验的篮球视频解说导演”。优势必须落在作品里：数值不被改写、画面不乱指、解说不过度归因、修改后可以重新导出。产品从“演一次”延伸到“下次还能继续”：用户的视频存入本机，回合和来源可编辑，历史可恢复，每份成片对应确定版本。当前主入口是项目工作区 `/projects.html`，服务只监听本机。

## 2. 三个候选方向与取舍

| 候选 | 能带来的价值 | 12 小时主要风险 | 本项目选择 |
|---|---|---|---|
| 通用 AI 解说员 | 视频一键生成热闹流畅的讲解，展示直观。 | 容易停留于复述；球员识别、数值和因果难核对，同类替代多。 | 保留语言转换能力，放弃自由生成全部事实。 |
| 篮球数字孪生与战术教练 | 三维重放、自由视角、阵型推演，视觉上限高。 | 依赖完整追踪、镜头标定和专用模型；单机位遮挡难解，现场输入未知。 | 只借用清楚的空间表达，不承诺三维重建或执教建议。 |
| 证据驱动的视频解说导演 | 官方指标、原视频和叙事逐项绑定，能演示也能审查。 | 对齐及数据口径仍是难点；若没有回合边界，需补充适配。 | 选为主方向，将有限时间投入可信闭环。 |

取舍依据是已公布任务的覆盖程度、现场可控性与可验收性。没有公布的评分权重不自行编造；如果正式规则要求特定模型或纯视频自动识别，需要调整实现，不能靠改变名称满足要求。

## 3. 官网任务如何落到交付

赛事官网要求处理火箭与独行侠历史视频及深度数据，自动定位、解读关键回合，在原视频上叠加标注，并生成对应解说；交付可运行作品、代码、说明和演示视频。完整细则仍待更新。[赛事官网](https://builderx.csdn.net/bcast-code#challenge)

| 官网任务 | 对应模块与演示证据 | 当前边界 |
|---|---|---|
| 深度数据运用 | 指标字典、来源引用、筛选理由、逐句证据。 | 演练值是合成值；正式字段待适配。 |
| 定位关键回合 | 已给定回合的筛选、时间轴跳转、片段定位。 | 未证明从任意电视视频独立切分全部回合。 |
| 箭头、色块、球员标注 | 输入追踪按视频时钟叠加；新增人工箭头、区域和文字编辑。 | 人工静态标注独立复核，不改变原追踪校准，也不是自动认人。 |
| 准确同步的篮球解说 | 两种口径、结果时刻约束、字幕与成片；macOS 可选本地中文配音。 | 默认无音轨；语音只朗读已有字幕，不保留原音，不替代云 Agent。 |
| 可运行及可交付 | 持久项目、SQLite 历史、质量面板、后台任务、代码及操作文档。 | 本机单用户；正式规格、提交方式和赛前代码许可待确认。 |

自动化差距必须正面呈现：如果赛方提供事件及回合时间，定位主要是可靠对齐；如果仅提供原视频和散列统计，回合切分就是新增任务。此时优先接入事件时间并校准，不把人工划段伪装为视觉模型识别。

## 4. 从成熟产品借什么，不复制什么

Synergy 的投篮点能打开对应视频，Hudl 将统计与片段相连。这说明最值得复用的是“一个结论立即回到证据”的交互。CourtLens 增加的目标是将证据进一步编排成可播放的解释，而不是搭建另一套庞大球探数据库。[Synergy 帮助](https://support.synergysports.com/support/solutions/articles/77000576098-shot-chart-viewing-and-tagging-in-the-synergy-editor)、[Hudl Assist](https://www.hudl.com/products/assist/basketball)

Second Spectrum 与 GeniusIQ 的增强转播可借鉴标注时机及阅读顺序。FIBA U19 案例使用多台固定设备追踪，不能据此宣称单段广播视频也能恢复同等空间信息。[GeniusIQ 案例](https://www.geniussports.com/newsroom/geniusiq-offering-fans-a-new-game-watching-experience-at-fiba-u19-basketball-world-cup/)

HomeCourt 的启发是“识别条件与反馈闭环”一起设计；其有利拍摄条件包括清晰球场线和单射手，不能直接套用到多人遮挡。用户提供的 Smartshot 照片同样是体验参考，不是本项目的技术验证。[HomeCourt 设置说明](https://www.homecourt.ai/faq/setup)

EPV 研究启发我们讲清终结之前的创造过程，但 CourtLens 不以逐回合记录冒算 EPV。Synergy 官方文档也说明深度上下文包含人工标注；专业叙事需要谨慎证据，并非挂上 AI 名称就能自动获得。[EPV 原论文](https://www.lukebornn.com/papers/cervone_ssac_2014.pdf)、[Synergy API 说明](https://developer.sportradar.com/basketball/reference/synergy-basketball-faqs)

## 5. 实际模块与指标边界

分析链路分为输入校验、时间与画面校准、证据编译、编辑排序、解说规划、播放导出六部分。产品层新增项目工作区、CSV 接入、人工标注、历史和任务。用户可从视频建立占位回合，随后填写真实事件；CSV 提供已对齐时间与指标，JSON 保留更完整轨迹。两种输入都不会凭空产生专业深度指标。

项目视频上传给本机服务并保存到工作区，刷新或重启后可继续。每次保存新增 revision；过期保存返回 409，用户可以保留草稿再合并。网页修改会撤销整体复核，显式草稿和未完成占位阻断导出。后台任务冻结数据版本与媒体副本，排队后继续编辑不会污染原任务；完成后才开放 MP4、字幕和分析文件。中断任务明确失败，由用户重试，不伪装断点续跑。

空间层分开处理两种来源：追踪图层受镜头校准与采样范围约束；人工图层要求 `origin=manual`、画面复核和来源说明，只是短时间静态标记。它可以在原追踪未校准时独立显示，但不会把原 `calibrated` 改成真，也不证明战术因果。导出共享证据与字幕计划；默认无音轨，macOS 可选本机中文配音。语音成功后附记录，失败不开放无声中间视频；两种模式都不混入原音。

三项指标各守自己的含义。xFG% 按来源定义呈现，0.62 显示为 62%；若输入叫“难度分”，先核对量纲和方向，不能直接改名。Gravity 保留原始值，最近防守者距离只能是独立几何量。演练 Leverage 明确限定为 0–1 的“回合胜率机会差”，不是球员累计 Leverage Score；正式数据若不同，要修改适配与逻辑，不能截断数值掩盖差异。编辑排序只是公开的选片规则，不是官方综合能力分。[NBA on AWS](https://aws.amazon.com/sports/nba/)

当前本地问答在已有证据范围内工作，不能称为已完成云端大模型推理。可选 Bedrock 分支允许模型调用证据工具，再选择已有声明 ID；本地编译最终文字与数值，不接受模型自由补出的数字。它已经有模拟协议测试，但实际模型行为、可用区域、成本及延迟仍须实调。若比赛明确要求大模型 Agent，仅有本地规则链路不能代替此项验收。

“标记 official”也不是真实性认证。它只是输入声明；现场仍要核对组织方原件、字段说明和文件校验值。原始事实、解释推断和不可用信息分别表达，缺失值不默认为零。

## 6. 优势必须怎样证明

| 待验证优势 | 公平的强替代 | 应收集的证据 |
|---|---|---|
| 数值和解释可追溯 | 直接把官方统计套入固定模板。 | 同一批回合逐句核查数字、单位、证据 ID，报告错误与缺失。 |
| 画面更易理解 | 原视频加专业人工字幕和基础圈画。 | 同一时长、同一信息量比较；检查标注遮挡、时间错位及解释是否多余。 |
| 修改及复现更省事 | 熟练剪辑者使用现成模板。 | 同素材计时修改、复核及重导出；检查历史恢复、冲突不覆盖、任务版本固定。 |
| 有限 Agent 编排更稳 | 直接让多模态模型自由解说。 | 注入缺失字段和误导问题，检查是否编数、串回合或承认不足。 |

不使用被故意削弱的基线。模板可能更快、更稳，人工解说可能更懂球；如果 CourtLens 没有实测赢过，就陈述功能差异，不写“显著优于”。

最脆弱的假设有三项：官方数据能找到对应视频时刻；深度指标有足够解释上下文；赛题允许复用现有准备代码。它们分别由现场数据检查、证据稽核和规则确认解决。产品还依赖用户愿意完成必要复核，且现有 FFmpeg 流程能满足其片段规模；尚无真实用户记录证明这一点。合成演练只能检验软件行为，不能证明真实 NBA 战术准确率、观众理解提升或商业需求。

## 7. 官方数据适配与现场验收

领取数据后的第一个成果应是可读的输入清单，不是漂亮首页。记录文件来源、版本、编码、时间基准、单位、缺失符号与允许使用范围；保留原件，适配层另存标准输入。球员、球队、比赛 ID 按字符串处理，先检查前导零、重名及事件关联。统计定义以赛方字典为准，原文解释与内部字段建立映射。

从三个已知事件建立首批锚点：节次和计时钟、视频秒数、事件结果同时核对。暂停、回放和广告会破坏单一线性偏移，因此使用分段映射。CSV 必须填写映射后的视频秒数；错误行号指记录结束的物理行，非逻辑回合序号。非空 Leverage 必须显式确认内部口径。切镜后重新判断追踪校准；人工标注另行核对，平面单应性需留独立检查点，不能恢复球的三维轨迹。

现场验收按以下次序进行：

1. **语义验收：** 字段方向、单位和范围正确；缺失值显示不足；不同 Leverage 版本不混算。
2. **时间验收：** 起止包含完整解释动作；出手数值在正确时刻出现；回放画面不误用实时时钟。
3. **画面验收：** 标注不越镜头插值、不覆盖关键动作；没有可信位置时改用边栏或明确的示意图。
4. **叙事验收：** 对演示中每句重要解释人工核对，区分观察与推断，禁止根据结果编造心理状态。
5. **产品及交付验收：** 用真实输入建项目，保存后刷新与重启；检查草稿阻断、冲突保留、历史恢复、冻结导出和取消。干净环境重新导出并独立播放，代码与素材权限、规格逐项核对。若要求语音，验证最终环境的本地配音、音轨与字幕同步，不能以无音轨成片替代。

另外保留缺失指标、错位锚点和未校准镜头三类故障输入。系统应该给出可理解的降级结果，而不是继续画错。验收数字以真实日志为准，本稿不填入尚未测得的准确率、误差或耗时。

## 8. 两至三人、十二小时安排

| 时段 | 首要产出 | 三人分工 |
|---|---|---|
| 0–1 小时 | 读正式规则、核对数据、确认可复用范围、选首个回合。 | 全员共同定口径，避免各自假设。 |
| 1–3 小时 | 一个真实回合贯穿输入到播放。 | A 适配与对齐；B 播放标注；C 指标核查与叙事。 |
| 3–6 小时 | 难度、引力、关键度三类代表回合。 | A 证据与云分支联调；B 交互与导出；C 篮球分析、叙事与逐句核查。 |
| 6–8 小时 | 可连续播放的演示和故障降级。 | 交叉验收，不由作者独自确认正确。 |
| 8–10 小时 | 修复阻断项、冻结功能、完整成片。 | 只修缺陷，停止增加三维等支线。 |
| 10–12 小时 | 打包、干净启动、录演示、练答辩并按规则提交。 | 留出重导出和上传余量。 |

两人队伍中，A 负责工程与数据，包括适配、指标口径、证据逻辑和后端；B 负责界面演示与素材复核，包括标注、字幕、导出检查和路演。三人时由 C 独立负责篮球分析、叙事与交付核查，B 聚焦界面和视频流程，关键解释交叉复核。任何阶段都保留可运行版本；第三小时仍无法闭环时，先收缩为一个回合。云不可用时披露本地模式；若云为硬性要求，则列为阻断问题。

## 9. 未来商业方向：仅作为待验证假设

可能客户包括赛事内容团队、球队视频分析岗位和篮球教学内容创作者。他们可能需要把已有合法视频与统计更快转成可审核讲解。当前能提供本机单用户试用，不具备账户认证、团队协作、计费、云端保存或公共分享。按席位或处理量收费只是候选，没有客户访谈、付费样本或市场规模验证。

下一步从少量真实工作流开始：记录建立项目、复核、返工与导出耗时，观察谁审核、错一个数字造成什么成本，以及用户是否愿意为可追溯结果付费。若证据支持团队协作，再建设租户隔离、权限、审计、任务配额、备份删除和运营监控，不能把本地 SQLite 包装成 SaaS。正式经营还取决于素材授权。代码许可证不能代替 NBA 视频权利，免费 API 试用不自动包含公开发布许可。[Sportradar 条款](https://developer.sportradar.com/sportradar-updates/page/terms-and-conditions)

## 10. 可直接复用的报名摘要

CourtLens 观赛透镜是一款证据驱动的篮球复盘与视频解说工作台。它面向赛题给定的投篮难度、球员引力和关键度，筛选已有回合，将解释绑定到来源与视频时刻，用箭头、区域、标签和字幕呈现可核查的判断。当前本机产品支持视频持久导入、CSV 与 JSON、人工标注、历史版本、质量检查和后台成片导出，macOS 可选本地中文配音。作品兼顾普通观众与分析视角；赛前使用明确标记的合成素材验证流程，真实 NBA 数据待现场适配，云规划分支尚未实调。

## 11. 三分钟路演稿

**0:00–0:25｜问题。** 大家看到这个三分进了，解说通常会说“漂亮”。但真正值得解释的可能发生在前两秒：谁吸引了防守，哪片空间被打开，这个回合为什么重要？我们的作品 CourtLens，想把这些“为什么”解释回比赛画面。

**0:25–0:55｜先看产品。** 这里是项目工作区。视频保存到本机，回合可以修改，刷新后还能继续。打开这一段，系统会说明选它的依据是投篮条件、引力还是关键度。点击证据回到对应时刻。今天展示的是合成演练，每个演练值都有明确标签。

**0:55–1:30｜展示编辑闭环。** 我们暂停画面，加一条人工箭头，核对它的时间区间再保存。这里会保留人工来源，不把它说成自动追踪。回到项目页复核后，可以导出这个版本。随后继续编辑，已经排队的任务仍使用刚才冻结的数据和视频。字幕只有到明确的结果时刻才宣布结果。

**1:30–2:05｜技术选择。** 本地链路负责校验、证据编译和视频编排。历史版本与冲突检测保护修改，后台任务完成核验后才提供下载。macOS 可以本地朗读这些同步字幕，语音失败不会混交无声视频。这个语音工具不是云模型；可选云规划分支只选择已有声明，尚未真实云调用。

**2:05–2:35｜展示边界。** 没有轨迹时不会自动找出球员，未校准时停止追踪图层，已复核人工图形单独处理。没有指标就显示不足，草稿也不能直接导出。正式 NBA 输入到场后，我们还要核对数据口径、时间和每句解释，不能拿合成视频证明真实识别准确率。

**2:35–3:00｜收束。** CourtLens 希望交付的不只是更热闹的解说，而是一段观众看得懂、分析者查得到依据的视频。你可以问“为什么选这一球”，也可以追问“证据在哪里”。这两次追问，应该都能在作品里得到答案。

## 12. 十个尖锐答辩

**1. 这不就是规则模板，为什么叫 Agent？** 当前稳定核心确实包含确定性规则，我们不会把它包装成大模型。工具规划分支让模型先读取证据、再选声明，应用负责校验和执行；它尚需真实云联调。是否达到比赛对 Agent 的要求，以完整规则验收。

**2. 你们的 AI 自动识别了哪些东西？** 当前自动完成已给定回合的筛选、证据组织和呈现；也支持人工建回合、CSV 接入和静态标注。它不会从任意广播视频独立认人、恢复三维或识别全部战术。新建占位不是视觉识别。

**3. 关键指标是你们自己发明的吗？** 不是。正式赛题使用来源给定指标，我们做定义映射和解释。演练 Leverage 有明确限定，不能等同官方球员累计分。我们的编辑排序也是选片规则，不冒充官方指标。

**4. 为什么模型不能自由发挥，岂不是很死板？** 数字和事实不需要自由发挥。当前让模型在可核实声明中选取，换取可审查性；表达丰富度仍可在经过约束的版本中改进。若牺牲了故事性，必须用同素材对照检验这个取舍。

**5. 你如何证明解释的因果正确？** 我们不把相关性自动写成因果。先描述可见位置与来源统计，再给有条件解释。缺少传球、跑位或防守责任证据时，不断言“某人造成得分”或“某人漏防”。

**6. 换一个机位，箭头还准吗？** 不保证。追踪须逐镜头校准并用独立检查点检验。人工箭头只对已核对时间段有效，不跨声明镜头，不随球员移动，也不改变自动追踪校准。相机移动时缩短区间或重画。

**7. 如果正式数据没有轨迹和回合边界？** 先用事件时间与画面锚点定位；也可人工建立并审核回合、圈画证据，诚实保留人工来源。若规则要求全自动切分，则仍有待完成项，不能用手工结果冒充模型能力。

**8. 模板解说或熟练剪辑师可能更好，你们凭什么赢？** 可能如此。我们接受强基线，比较相同回合的可追溯性、错位、返工和复现。未完成对照前，不声称更快、更准；演示重点是把选片理由、依据和导出连成可操作流程。

**9. 有真实观众或商业验证吗？** 目前没有，因此不报满意度、理解提升或付费意愿。已有证据是软件链路与合成输入下的行为；真实素材核查和观众比较是下一阶段工作，商业方向只是待验证假设。

**10. 这已经是可商业运营的 SaaS 吗？** 目前是能保存、重开、编辑与导出的本机单用户产品，没有账号、多租户和计费。公开代码不包含对 NBA 素材的自动授权。云规划尚未实调，真实用户和 Windows 实机验证也未完成，不能宣称已上线成熟云服务。
